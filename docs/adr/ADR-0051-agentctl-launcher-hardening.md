# ADR-0051 — Harden agentctl validation and scientific run lifecycle

- **Status:** Accepted
- **Date:** 2026-10-01
- **Decision owner:** project owner
- **Relates to:** ADR-0044, ADR-0048, ADR-0050, A3 in `docs/roadmap.md`

## Context

An audit of `scripts/agentctl.py` identified risks in the governed scientific
launcher and local validation path: inherited host secrets reach study code;
validation-matrix commands use a shell; PID-only lock checks can confuse a reused
PID with the original process; direct lock writes can be interrupted; setup failures
can leave copied run state; greedy CLI arguments make the `--` boundary optional;
and Windows timeout handling may leave descendants running.

These are control-plane concerns because they affect which commands execute and
how governed work is isolated, recorded and cleaned up. The mitigation must be
explicit about its limits: environment filtering is not an OS security sandbox,
and verifying or terminating every descendant is not promised across platforms.

## Decision proposal

1. Give the scientific child and its environment synchronization process only an
   explicit environment-variable allowlist. Add run-scoped `HOME` and pass only
   launcher-owned `SYMBIONT_*` values. This reduces accidental credential
   inheritance; it does not prevent code running as the same OS user from reading
   other accessible files or obtaining credentials by other means.
2. Parse validation-matrix commands with `shlex.split()` and execute with
   `shell=False` only when tokenized argv matches a repository-maintained exact
   argv form or begins with a structured token-array prefix maintained in code.
   Do not use string-prefix matching. Unknown commands fail closed. TOML remains
   data, not shell code.
3. Record process-start identity with lock PIDs and compare it when the platform
   exposes a reliable token. On Linux use `/proc/<pid>/stat` start time. On systems
   without a comparable token retain conservative PID liveness behavior and state
   that limitation; do not claim cross-platform PID-reuse immunity.
4. Write lock and receipt JSON via a same-directory temporary file, flush it, then
   atomically publish it. Exclusive lock creation must not overwrite a concurrent
   reservation. Existing malformed locks remain an explicit inspection case.
5. Create run-scoped `HOME` before any auxiliary process can read user configuration.
   Clean temporary snapshot, worktree-copy, environment and home data if setup fails
   before a child is launched. Preserve an attempt receipt with an explicit
   `SETUP_FAILED` state when failure occurs before the child starts; do not represent
   that attempt as a scientific execution.
6. Require `--` between `agentctl run start` options and the child Python command;
   do not silently reinterpret omitted separators.
7. On Windows request a new process group and use a process-tree termination
   mechanism on timeout. This is best-effort platform behavior, not a guarantee
   against detached or escaped descendants. POSIX resource policy remains unchanged.
8. Include canonical `sys.prefix` and `sys.base_prefix` in
   `ExecutionFingerprint`, so a venv launched through a symlink to its base
   interpreter is distinguishable from that base environment. Preserve canonical
   `sys.executable` identity comparison from ADR-0050.

Build child environments from an empty mapping, copying only explicitly approved
host variables. Never inherit host `SYMBIONT_*` values: those are added individually
only when generated by the launcher. Atomic JSON publication must `fsync` the
temporary file before rename/replace; syncing the containing directory is an
additional durability measure. Parse Linux `/proc/<pid>/stat` by locating the
parenthesized `comm` boundary, not by splitting the complete line naïvely. Require
the `--` separator before interpreting child arguments; after it, do not parse or
reinterpret any child flags.

The proposal concerns accidental exposure, shell injection from the validation
matrix, stale or partial state, and predictable lifecycle behavior. It does not
turn `agentctl run start` into a hostile-code sandbox or alter scientific
authorization, resource ceilings, evidence policy, or the scope of ADR-0050's
direct-child verification contract.

## Alternatives considered

- **Continue inheriting the full host environment.** Rejected because unrelated
  credentials are not required by a pinned scientific child and can be exposed
  accidentally.
- **Keep `shell=True` and trust changes to the TOML matrix.** Rejected because a
  checked-out configuration file would then be executable shell input.
- **Use `shlex.split()` alone without an allowlist.** Rejected because tokenization
  removes shell interpretation but would still permit arbitrary executables and
  arguments from the matrix.
- **Automatically delete every malformed or stale lock.** Rejected because a
  malformed lock lacks trustworthy ownership evidence; destructive recovery must
  not guess whether work remains active.
- **Claim process-tree containment on every platform.** Rejected because process
  detachment and platform semantics are outside this narrow hardening contract.

## Consequences

### Benefits

- Study code no longer inherits arbitrary environment secrets by default.
- Validation configuration cannot request arbitrary shell syntax or an
  unapproved command prefix.
- PID reuse is detectable where process-start identity is available.
- Interrupted JSON updates are atomic, and pre-launch failures do not strand large
  transient run directories.
- CLI and receipt behavior become more explicit and testable.

### Costs and limitations

- Validation commands outside the allowlist require a reviewed code change.
- Tools that genuinely need additional environment variables require explicit
  allowlist review; implicit host inheritance is not a fallback.
- A previously corrupted lock still requires owner inspection.
- PID-start comparison is platform-dependent; on unsupported platforms liveness
  checks remain conservative rather than proving identity.
- Windows process-tree timeout behavior needs Windows-specific validation and is
  not a security boundary.
- Environment filtering does not isolate filesystem, network, credentials exposed
  through accessible files, or descendants. Use OS-level isolation for hostile
  code.

## Acceptance criteria

- [x] Project owner explicitly accepts this ADR.
- [x] Tests prove environment secrets and inherited `SYMBIONT_*` values are omitted while required launcher values
      and run-scoped home are present.
- [x] Validation rejects shell metacharacter payloads and unapproved commands;
      allowlisted commands execute without a shell.
- [x] PID reuse is tested with a changed process-start token; unsupported-platform
      fallback behavior is covered or explicitly documented.
- [x] Atomic lock creation is tested for concurrent reservation and interrupted
      writes; malformed pre-existing locks remain non-destructive.
- [x] Failure injection proves setup cleanup before launch and a `SETUP_FAILED`
      attempt receipt is retained without claiming a scientific execution.
- [x] CLI tests prove `--` is mandatory and child flags remain child arguments.
- [x] Windows timeout handling remains explicitly unverified in this POSIX
      environment and is not claimed as validated behavior.
- [x] Fingerprint tests show `sys.prefix`/`sys.base_prefix` mismatch fails before
      target code.
- [x] The focused suite, repository governance verification and applicable static
      checks pass; full-suite results are reported separately.

## Decision

Accepted by the project owner on 2026-10-01. Acceptance authorizes implementation
but does not itself close A3 or any implementation criterion. The listed
mitigations are not a sandbox.
