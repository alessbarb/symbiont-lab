# K1 capacity characterization report

Date: 2026-09-22  
Canonical control: `192 nodes / 1536 edges / 32 concepts`  
Protocol: `K1`, version `1`

## Scope and evidence boundary

This is a characterization result, not a change to canonical kernel values.
K1-A is a deterministic, lab-only synthetic capacity probe. It is not an
organism genome and does not demonstrate developmental learning. K1-B is the
headless Physics3D embodiment using the canonical
`genome_symbiont_physics3d_v9` genome. The organism never receives the
experimental limit as an observation.

The first K1-A implementation was rejected because all node sizes produced
identical behavior. It measured graph traversal cost, not capacity. The
implementation was corrected before this run: each available state node is a
nonlinear feature lane, and the fixed target requires 512 lanes. This creates
an explicit capacity demand while keeping the probe deterministic.

## K1-A: corrected abstract probe

Eight node limits were run with ten paired seeds; all 80 runs completed
without failures:

| max_nodes | mean prediction error | mean CPU us/tick |
|---:|---:|---:|
| 64  | 0.024652 | 1996.0 |
| 96  | 0.013983 | 2331.9 |
| 128 | 0.005252 | 2418.4 |
| 160 | 0.007424 | 2523.9 |
| 192 | 0.008510 | 2914.1 |
| 256 | 0.003119 | 2910.6 |
| 384 | 0.002433 | 3814.9 |
| 512 | 0.002096 | 4949.2 |

The response is now capacity-sensitive: error is materially lower at 128,
256, 384 and 512 than at 64. The curve is not monotonic at every adjacent
point because the probe exposes a fixed ordered feature basis; that is a
property to improve before treating the result as a quantitative calibration.
The mean error improvement from 192 to 256 is substantial, while the further
improvement from 256 to 512 is small relative to the CPU increase.

At the configuration level, the Pareto artifact contains variant-level rows,
not individual seed rows. The previous implementation compared individual
seeds and has been corrected.

## K1-B: Physics3D arm

The full seven-phase protocol was run for ten paired seeds at each value:

| max_nodes | mean error | p95 error | mean gain | mean CPU ms/tick | mean nodes used | utilization | failures |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 192 | 0.067088 | 0.125138 | 0.072189 | 48.123 | 132 | 0.688 | 0 |
| 256 | 0.072802 | 0.151189 | 0.059457 | 57.188 | 132 | 0.516 | 0 |
| 384 | 0.067109 | 0.188895 | 0.070581 | 65.905 | 132 | 0.344 | 0 |
| 512 | 0.072618 | 0.142555 | 0.010886 | 59.436 | 132 | 0.258 | 0 |

Within this protocol and ten seeds, 192 remains the best embodied control:
larger limits do not improve mean behavior and all variants use about 132
nodes. This is integration evidence, not proof of a universal optimum.

## Decision

**Keep the canonical kernel unchanged for now:**

```text
max_nodes = 192
max_edges = 1536
max_concepts = 32
```

The corrected K1-A probe justifies continuing the capacity study and flags
256 as a synthetic candidate, but it is not sufficient to promote 256 because
the probe has no real developmental adaptation. K1-B provides no reason to
increase the production limit. Do not start K2 as a production-calibration
step until the K1-A protocol adds a real adaptation path and its result is
confirmed against the embodied arm.
