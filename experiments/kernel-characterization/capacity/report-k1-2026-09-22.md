# K1 capacity characterization report

Date: 2026-09-22  
Code commit under test: `1c70371e`  
Canonical control: `192 nodes / 1536 edges / 32 concepts`  
Protocol: `K1`, version `1`

## Scope

This report covers the first capacity sweep only. It is a characterization
result, not a change to canonical kernel values. K1-A is an abstract synthetic
screen; K1-B is the headless Physics3D embodiment using the canonical
`genome_symbiont_physics3d_v9` genome. The organism never receives the
experimental limit as an observation.

## K1-A: abstract arm

Eight node limits were run with ten paired seeds:

```text
64, 96, 128, 160, 192, 256, 384, 512
```

All 80 runs completed without failures. However, the behavioral metrics were
identical at every size:

| max_nodes | mean prediction error | mean predictive gain | mean CPU us/tick |
|---:|---:|---:|---:|
| 64 | 0.147391 | 0.028109 | 192.04 |
| 96 | 0.147391 | 0.028109 | 265.35 |
| 128 | 0.147391 | 0.028109 | 361.35 |
| 160 | 0.147391 | 0.028109 | 522.58 |
| 192 | 0.147391 | 0.028109 | 574.22 |
| 256 | 0.147391 | 0.028109 | 847.79 |
| 384 | 0.147391 | 0.028109 | 1186.44 |
| 512 | 0.147391 | 0.028109 | 1613.86 |

### Interpretation

K1-A is useful as a deterministic execution and cost screen, but it does not
currently discriminate cognitive capacity. Its graph probe fills the limit
and its extra nodes do not provide a distinct learned capability. Therefore
these results must **not** be used to choose a node limit. This is exactly the
failure mode the characterization campaign was intended to expose: a hot-path
benchmark is not a capacity experiment.

## K1-B: Physics3D arm

The full seven-phase protocol was run for ten paired seeds at each value:

| max_nodes | mean error | p95 error | mean gain | mean CPU ms/tick | mean nodes used | utilization | failures |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 192 | 0.067088 | 0.125138 | 0.072189 | 48.123 | 132 | 0.688 | 0 |
| 256 | 0.072802 | 0.151189 | 0.059457 | 57.188 | 132 | 0.516 | 0 |
| 384 | 0.067109 | 0.188895 | 0.070581 | 65.905 | 132 | 0.344 | 0 |
| 512 | 0.072618 | 0.142555 | 0.010886 | 59.436 | 132 | 0.258 | 0 |

### Interpretation

Within this protocol and ten seeds:

- `192` is on the Pareto frontier: lowest mean error, highest mean gain,
  lowest CPU cost and highest utilization.
- `384` is behaviorally almost tied with `192`, but costs substantially more
  and has worse p95 error.
- `256` and `512` do not improve mean behavior.
- `512` shows a clear loss in mean predictive gain.
- No configuration saturated the node ceiling: all runs used approximately
  132 nodes.

The result does **not** prove that 192 is a universal cognitive optimum. It
does show that this K1-B protocol provides no evidence for increasing the
canonical node limit.

## Decision

**Keep the canonical kernel unchanged:**

```text
max_nodes = 192
max_edges = 1536
max_concepts = 32
```

Do not promote any experimental value to production. In particular, do not
increase `max_nodes` to 256, 384 or 512 based on this campaign.

## Required follow-up before calibrating K2

K1-A must be corrected so that additional capacity can create distinct useful
representations rather than merely increasing graph traversal cost. The next
implementation should add a fixed task demand and a real developmental
adaptation path, then repeat K1-A with the same paired seeds. Only after that
arm demonstrates a capacity-sensitive response should K2 connectivity be
started.

K1-B should then be rerun only for the survivors of the corrected abstract
screen. The current K1-B data is an integration and regression baseline, not a
final physiological calibration.
